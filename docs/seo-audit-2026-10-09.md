# ChatDVT discoverability audit — 09/10/2026

## What is confirmed

The user reports that searching/asking Gemini about `ChatDVT` no longer produces the earlier recognition of the project, its author and its history. The earlier screenshot is evidence of a previous answer, not of the current indexed state. No Search Console account, actual Google crawler logs or current Gemini response was inspected.

The clearest verified regression is homepage identification. Commit `7fc24b6` (06/10/2026) changed `HomePage` metadata from `Đặng Văn Tiến — Mobile Developer & ChatDVT` to `Đặng Văn Tiến — Mobile Developer`, and removed ChatDVT and its Discord/web chatbot description from the homepage meta description. A September snapshot (`7ff11d3`) identified the site as `ChatDVT Community` / `ChatDVT Portal`; the site now presents a personal mobile portfolio with ChatDVT in a side-project section. This weakens prominent brand identification. It does not by itself prove the cause of Gemini's changed answer.

There is also an important source-of-truth trap: `client/index.html` and the i18n homepage metadata strings retain ChatDVT, while the current homepage values in both `src/api/seo.ts` and `HomePage.usePageMeta` omit it. `HomePage.usePageMeta` is collected by `client/src/seo-entry.tsx` through `PageMetaCollector`; `renderPublicHtml` passes the collected metadata into `injectSeoMeta`. The effective live title and description come from the component. Checking only the HTML template or translations misses this regression. For the history article, the static SEO table contains a detailed development summary, but the component's excerpt replaces it in the response.

The product and article have no `nosnippet`, `max-snippet:0` or `data-nosnippet` restriction. Product JSON-LD already identifies ChatDVT as a SoftwareApplication, references its real repository and names Đặng Văn Tiến as creator. Article JSON-LD names the same Person as author/publisher. This does **not** authenticate a real Googlebot request or establish what Google's IPs can fetch. A previous audit documented a Cloudflare Browser Integrity Check denial; it was not reproduced with these requests today.

The public article API returned 404, while the HTML route serves the built-in published fallback article. Current client code preserves that fallback on a rejected API request. This is not evidence that the article becomes unavailable to Search, since its full text is in the initial HTML.

## Other weaknesses and limits

- The article's effective meta description uses its narrative excerpt (a disagreement with coworkers), replacing the more informative history summary in the route metadata table. The full article is present, so this is a summary weakness rather than a crawl blocker.
- Product introduction in Vietnamese says `Mình làm ChatDVT`; the explicit full author name is in metadata/schema and the shared footer. A concise visible sentence tying `ChatDVT`, `AI chatbot/Discord bot` and `Đặng Văn Tiến` together would make identification clearer.
- The new `/me` design in this working tree shortened the ChatDVT paragraph and removed group 8D/Discord.js/Gemini details and the direct product link. It is **not yet on the inspected live page**, so it cannot explain the current report. Retaining a short origin sentence and links to `/discord` and the history article would avoid further weakening these connections.
- The external web retrieval tool returned an older five-line noscript description for `/discord` and failed to open the article, while direct HTTP retrieved complete current content. This shows a difference between retrieval paths or stored versions; it does not prove Google's index is missing or identify Cloudflare as the cause.
- The current SEO tests check readable facts, schemas and local HTTP behavior. They do not require ChatDVT in the homepage title/description and cannot verify indexing, ranking or Gemini source selection. Passing them did not detect the homepage metadata regression.

## Recommended order

1. Inspect **indexed** `/discord` and `/blog/chatdvt-phan-1` in Search Console: index status, last crawl, Google-selected canonical and crawled HTML. Compare those with Live Test; inspect `/` too. This distinguishes an outdated/thin indexed version, fetch failure and a correctly indexed page that Gemini did not use.
2. Under the user's subsequent constraint, keep Home and its metadata unchanged. Strengthen accurate ChatDVT identification on its own product page instead; the homepage title change is a potential weakening of brand prominence, not a technical error that must be reversed.
3. Make the product's visible definition explicit, retain a brief factual development sequence and link to the original history article. Keep the approved profile design while restoring its product/history links.
4. Align component and server metadata so future design edits cannot silently remove this identity. Validate the emitted HTML, not just the static metadata configuration. Add a meaningful regression assertion for the agreed homepage/product identity when implementing the fix.
5. After any approved deployment, verify production HTML and use Search Console to request recrawling of the corrected URLs. No fixed recrawl time, ranking or Gemini answer can be promised.

No application or SEO source was changed in this audit. The prior `/me` implementation remains in the working tree.

## Authorized follow-up

The user subsequently required Home to remain a personal portfolio, accepted the alternative of strengthening Discord/history/Me, and said “Ok làm đi”. The local implementation therefore keeps Home source and full VI/EN rendered HTML identical to their state before this follow-up. Following the user’s request to keep the interface simple, it adds only a brief linked creator/origin introduction to Discord and retains the existing link to the full blog story, restores product/history links in Me, and shares product/article metadata between browser and server. The article retains its body and original publication/modification dates; its schema now references the ChatDVT product as its subject. Local regression checks cover the effective HTML, CMS excerpt override, VI/EN canonicals, related links and unrelated articles. These changes have not been deployed or verified in Search Console.
